1 · Technology Stack

MediLink is a role-based hospital management system built with a decoupled architecture. A React SPA communicates with a Django REST API via JSON HTTP. All services are containerised with Docker Compose on a private bridge network.

2 · Docker Service Topology

Six containers on a private medilink_network bridge network. Only frontend :3000 and backend :8000 expose host ports. All other services communicate exclusively over the internal network.

🌎 frontend

  • nginx:alpine3000:80
  • Serves React build (SPA)
  • Proxies /api/* to backend:8000
  • Forwards Set-Cookie headers
  • proxy_cookie_path rewriting

⚙ backend

  • python:3.11-slim8000:8000
  • Django + Gunicorn 4 workers
  • Runs migrate on startup
  • Collects static to /staticfiles
  • Depends on: db, redis

🗄 db (PostgreSQL 15)

  • postgres:15-alpine
  • Internal only, no host port
  • Volume: postgres_data
  • Health-checked (pg_isready)

🔴 redis

  • redis:7-alpine
  • Internal only
  • Volume: redis_data
  • Celery broker + result backend

⚡ celery-worker

  • Same image as backend
  • cmd: celery -A medilink worker
  • Processes async task queue
  • Shares backend code

🕐 celery-beat

  • Same image as backend
  • cmd: celery -A medilink beat
  • Fires periodic schedules
  • Checks overdue invoices / hr
3 · Authentication & Token Flow

Tokens are never exposed to JavaScript. Django sets them as HttpOnly cookies; the browser transmits them automatically. CSRF protection uses Django's double-submit cookie pattern with X-CSRFToken header.

🔐 Login → Establish Session

Browser
→
POST /api/users/login/   { username, password }
Django
→
authenticate() → RefreshToken.for_user(user) → _set_auth_cookies(response, refresh_token)
Set-Cookie
→
medilink_access=JWT; HttpOnly; SameSite=Lax; Max-Age=3600; Path=/
Set-Cookie
→
medilink_refresh=JWT; HttpOnly; SameSite=Lax; Max-Age=604800; Path=/api/users/token/refresh/
Response
→
{ user: { id, username, role, first_name, last_name } }   << NO tokens in body >>

♻ Silent Token Refresh (401 Interceptor)

Axios
→
Catches 401 → queues concurrent requests → POST /api/users/token/refresh/ (browser sends medilink_refresh cookie)
Django
→
Validates refresh JWT → blacklists old token → issues new access cookie + rotated refresh cookie
Axios
→
Replays original request; all queued requests resume automatically

🚪 Logout

Browser
→
POST /api/users/logout/ → Django blacklists refresh token in token_blacklist DB table
Set-Cookie
→
medilink_access=; Max-Age=0    medilink_refresh=; Max-Age=0    (cookies cleared)
Security properties:   HttpOnly → XSS immune · SameSite=Lax → CSRF safe · Secure=true (production, HTTPS only) · Token blacklist → server-side invalidation on logout

6 · End-to-End Data Flows
6.1 · Appointment Booking Flow
1

Patient browses doctors & availability

GET /api/users/doctors/ + GET /api/appointments/schedules/ populate doctor list and available time slots in the React Appointments component.

2

Patient submits booking

POST /api/appointments/ body: {patient, doctor, appointment_date, appointment_time, reason}. JWT cookie authenticates the request automatically via CookieJWTAuthentication.

3

DRF validates & persists

AppointmentSerializer validates unique_together constraint (doctor, date, time). Django ORM writes row to appointments_appointment table. Returns 201 Created with appointment data.

4

Doctor confirms & completes

PATCH /api/appointments/{id}/ transitions: scheduled → confirmed → completed. Doctor then creates a MedicalRecord linked to this appointment (OneToOne).

6.2 · Medical Record & Billing Flow
1

Doctor creates medical record

POST /api/medical-records/ with diagnosis, symptoms, treatment plan. Prescriptions and LabTests created as nested objects. VitalSigns recorded via separate endpoint.

2

Admin generates invoice

POST /api/billing/invoices/ linked to appointment. Auto-generates INV-XXXXXXXX. InvoiceItems added for consultation fee and tests. total = subtotal + tax - discount.

3

Patient views & pays

GET /api/billing/invoices/ (scoped to own). POST /api/billing/payments/ records payment. Invoice.sync_payment_status() auto-updates: pending → partially_paid → paid.

4

Celery Beat: overdue detection

Celery Beat fires billing.tasks.check_overdue_invoices every 3600s. Invoices past due_date with pending/partially_paid status are bulk-updated to overdue.

6.3 · Role-Based Access Control (RBAC)

👑 Admin

  • Full CRUD on all resources
  • Create & manage invoices
  • Record payments for any patient
  • View all appointments & records
  • Access Django /admin panel

🩺 Doctor

  • View own appointments only
  • Create & edit medical records
  • Write prescriptions & lab orders
  • Record vital signs for any patient
  • View patient list

🩹 Patient

  • Book appointments with any doctor
  • View own appointments & records
  • View own invoices & payments
  • Submit insurance claims
